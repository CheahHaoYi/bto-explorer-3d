# Data sources and attribution

## HDB Under Construction Buildings footprints

- **Publisher:** Housing & Development Board (HDB), catalogued on [data.gov.sg](https://data.gov.sg/datasets/d_e4aaf26891bfe398666f7a96fe81a972/view).
- **Local input used:** `data/raw/HDBUnderConstructionBuildings.geojson`. The supplied local file does not record when it was downloaded; its snapshot/retrieval date is therefore unavailable.
- **Catalog fields:** `OBJECTID`, `BLK_NO`, `ST_COD`, `ENTITYID`, `POSTAL_COD`, `INC_CRC`, `FMEL_UPD_D`, `SHAPE.AREA`, and `SHAPE.LEN`. The source does not include formal project names, project IDs, or BTO project boundaries.
- **Observed input count and geometry types:** 899 features; 893 Polygon and 6 MultiPolygon geometries. All 899 passed polygon geometry validation in the preparation run.
- **CRS:** No `crs` member is present. Coordinates are consistent with Singapore and the source is GeoJSON; the app assumes WGS 84 longitude/latitude (RFC 7946, EPSG:4326). This is an inference, not an explicit declaration in the supplied file.
- **Identifiers and transformation:** `ENTITYID` (unique in the supplied snapshot) is prefixed to form the app feature ID. Source geometry is retained without invented project groupings; block number and postcode are copied to selector fields, and original properties are retained for details/provenance. Representative points are calculated from each footprint only to populate the generic coordinate fields.
- **License/terms:** The catalog lists the Singapore Open Data Licence; check the [dataset page](https://data.gov.sg/datasets/d_e4aaf26891bfe398666f7a96fe81a972/view) and [licence](https://data.gov.sg/open-data-licence) when refreshing.
- **Browser asset:** `public/data/under-construction/buildings.geojson`, generated by `scripts/prepare_under_construction.py`. The dropdown labels each footprint by source block number and postcode; these labels are not official BTO project names.

## HDB Existing Building footprints

- **Publisher:** Housing & Development Board (HDB), catalogued on [data.gov.sg](https://data.gov.sg/datasets/d_16b157c52ed637edd6ba1232e026258d/view).
- **Local input used:** `data/raw/HDBExistingBuilding.geojson`. The raw file is local and excluded from Git; it does not contain a retrieval date. The catalog currently describes HDB Existing Buildings as updated every two months, with data from November 2025, but that catalog coverage is not asserted to be the coverage date of this local snapshot.
- **Fields used:** `ENTITYID` (fallback `OBJECTID`) for a stable derived ID; `BLK_NO`, `POSTAL_COD`, and `ST_COD` for the list; geometry for validity checks and representative points.
- **Observed input count and geometry types:** 13,436 features; 13,426 Polygon and 10 MultiPolygon geometries. Four geometries are topologically invalid and are skipped without repair. `ENTITYID` and `OBJECTID` are unique and non-null in this local snapshot.
- **CRS:** The file has no declared `crs` member. Coordinate bounds are consistent with Singapore, so the preparation assumes RFC 7946 WGS 84 longitude/latitude. This is an inference, not an explicit source declaration.
- **Region assignment:** Each valid footprint's Shapely representative point is assigned to the single region polygon that covers it. Geometry is not included in the regional index or modified; each output record contains its derived ID, source block number, postcode, street code, and representative-point coordinates. In this run all 13,432 valid footprints matched exactly one region; zero were unassigned or ambiguous. The count is by source footprint record, not a count of flats or dwellings.
- **License/terms:** The catalog lists the Singapore Open Data Licence; check the [dataset page](https://data.gov.sg/datasets/d_16b157c52ed637edd6ba1232e026258d/view) and [licence](https://data.gov.sg/open-data-licence) when refreshing.

## Master Plan 2025 Region Boundary (No Sea)

- **Publisher:** Urban Redevelopment Authority (URA), catalogued on [data.gov.sg](https://data.gov.sg/datasets/d_4ce0038f7ac689652350bb91b7fb92ed/view).
- **Local input used:** `data/raw/MasterPlan2025RegionBoundaryNoSea.geojson`. Its file retrieval date is unavailable. The source identifies itself as Master Plan 2025 region boundaries and its feature update fields are from December 2025.
- **Source fields used:** `REGION_C`, `REGION_N`, and each Polygon/MultiPolygon geometry. The source contains five named planning regions.
- **Boundary meaning:** URA describes these as indicative region polygons with sea areas excluded. Planning boundaries may not coincide with existing developments; they are used here as geographic groupings, not as HDB administrative boundaries.
- **CRS:** The source has no `crs` member. Coordinates are consistent with Singapore and the GeoJSON format; WGS 84 longitude/latitude is assumed, not explicitly declared.
- **License/terms:** See the dataset page and [Singapore Open Data Licence](https://data.gov.sg/open-data-licence).
- **Browser asset:** `public/data/regions/hdb-by-region.json`, generated by `scripts/prepare_region_hdb_index.py`. It contains the five source region geometries and the HDB block index with region counts; source raw files are not published.
- **Footprint assets:** The same generator writes five region-specific GeoJSON collections to `public/data/regions/buildings/{cr,er,nr,ner,wr}.geojson`. Each contains the assigned source HDB polygons/MultiPolygons and block identifiers. Geometry coordinates are retained as provided: no simplification, reprojection, repair, or imputation is performed. The app fetches a collection only after the region is selected. Current uncompressed file sizes range from about 6.2 MB (East) to 11 MB (North-East); network transfer may be compressed by the static host/browser.

The file `data/raw/MasterPlan2019Buildinglayer.geojson` is not used for region or HDB identification. It contains generic building polygons, but its `BLDG_TYPE` field is null on all observed 14,355 records, so it does not support a reliable HDB-only list. The current app uses HDB's own existing-building footprints for block records and URA's 2025 region-boundary dataset for region polygons.

## Basemap tiles

The Leaflet map requests the standard OpenStreetMap raster tiles from `https://tile.openstreetmap.org/{z}/{x}/{y}.png` only for the visible viewport. The map displays `© OpenStreetMap contributors` with a link to the copyright page. Follow the [OpenStreetMap tile usage policy](https://operations.osmfoundation.org/policies/tiles/): do not bulk-fetch or pre-cache tiles, do not suppress normal browser referrers, and do not bypass cache headers. The service is best-effort and has no availability guarantee. The HDB outline layer is a bundled local asset, so it remains visible over a neutral background if tile requests fail.

## HDB resale price history

- **Publisher:** Housing & Development Board (HDB), catalogued on [data.gov.sg](https://data.gov.sg/datasets/d_8b84c4ee58e3cfc0ece0d773c8ca6abc/view). The local snapshot contains five official CSV partitions from 1990 through October 2026. Its retrieval date is not recorded; the output explicitly stores `retrievedAt: null`.
- **Local inputs:** The two approval-date files from 1990–1999 and 2000–Feb 2012; the three registration-date files covering Mar 2012–Dec 2014, 2015–2016, and Jan 2017 onward. The columns used are `month`, `flat_type`, `block`, `street_name`, and `resale_price`. `town`, storey range, floor area, lease and flat model are not included in the block history output.
- **Coverage:** 988,657 transaction rows across all five partitions, January 1990–October 2026. All rows passed the date, price, address and known flat-type checks. The two historical `MULTI GENERATION` labels are normalized to `MULTI-GENERATION`; address/flat-type strings are uppercased and whitespace-normalized. No prices or missing values are imputed.
- **Date semantics:** The sources before March 2012 use approval month; March 2012 onwards use registration month. Annual histories keep the dataset's source month unchanged and disclose the date basis in the UI and output metadata.
- **Join:** Transactions are grouped by exact normalized block number + street name. To connect this address to HDB footprints, the preparation script builds a conservative street-code crosswalk from `HDBExistingBuilding.geojson` and `HDBPropertyInformation.csv`: every existing footprint block carrying a street code must have a property-information row, and all candidate street sets must share exactly one street. A block is mapped only to that street's resale history when the exact block+street transaction record exists. The same resolved code is applied to an under-construction footprint only when its exact block is listed under that street in Property Information. No fuzzy address matching is used.
- **Observed crosswalk counts:** 660 unique existing-footprint street codes; 477 resolve to one common street, 183 remain unresolved. The generated join contains 8,976 block/street-code pairs with transaction histories. Of 899 under-construction records, 66 have an exact block/street match through a resolved street code and property-information row; those addresses have no resale history in this snapshot.
- **Aggregation/output:** `scripts/prepare_resale_history.py` publishes annual median price and count, both overall and by flat type, at `public/data/resale/block-history.json` (about 11.2 MB uncompressed for this snapshot). Medians are rounded to the nearest whole SGD. It combines same-address records across source partitions while preserving the differing transaction-date basis in provenance. These are historical observations, not current valuations.
- **CRS:** Not applicable to the transaction CSVs. For the footprint crosswalk, HDB Existing Building and HDB Under Construction Buildings have no declared CRS; as documented above, their GeoJSON coordinate assumption is inferred and is not used to match price addresses.
- **License/terms:** data.gov.sg identifies the [Singapore Open Data Licence](https://data.gov.sg/open-data-licence); see the resale, property-information, and footprint dataset pages for current terms. The user's local download date is unavailable.
- **Browser use:** The app lazily loads and runtime-validates the derived asset when a block is selected. It draws a small SVG annual-median chart, lets the user filter by flat type, shows transaction counts and the latest six annual values, and links back to the source dataset.

The raw datasets remain local under `data/raw/`; only the derived block history is included under `public/data/`.

## Attribution practice

Keep attribution visible wherever sourced map tiles or public datasets are presented. Record the dataset name, publisher, source URL, license/terms, access date, relevant update date and transformations. For resale-price analysis, explain the transaction date range and that historical prices are not price guarantees.
